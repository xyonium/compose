用户的 `~/paper-search`（OWUI tool.py，xyonium/paper-search，main 分支）正在**增量取代** paper-search-mcp（mcpo 承载）。决策（2026-09-08，用户拍板）：不搬对方代码（同步 requests 无超时是已知坑，pubmed 挂起事故即源于此），只参考 endpoint/字段映射；保持混合架构作安全网，逐源迁移。

**三阶段**：Phase 1 补齐后端 search 源的直连适配器（arxiv ✅ 202067b；semantic/openalex/crossref/europepmc/core/biorxiv/medrxiv/iacr ✅ 5bf2d63，v2.9.0）；Phase 2 read 不动（自建 fallback 链已完整，后端 read 工具当快车道）；Phase 3 给 tool.py 套薄 FastAPI 服务实现 shim 的 4 个端点形状（`/papers/search_{source}` 等），firecrawl research-proxy shim 改 `MCPO_BASE_URL` 指向它 → paper-search-mcp 退役（shim 是其第二个消费者，只改 tool.py 不算完）。

**Phase 1 完成后端残留**：`_BACKEND_ALL_SOURCES` 只剩 doaj/google_scholar/ssrn/unpaywall/citeseerx/base/acm 作安全网（刻意不迁：doaj 字面源工作正常；scholar/ssrn/base/citeseerx 反爬不稳定源放后端隔离更好；unpaywall 仅 DOI 查询用于下载 fallback；acm 后端未实现）。**read_paper 已修前缀隐患**：直连源 paper_id 带自家前缀（arxiv:/semantic:/iacr:...），调后端 read 工具前剥离（_pfx==src 才剥）。v2.9 新 valve：semantic_api_key（403 降匿名+429 遵守 Retry-After）、core_api_key（401/403 降匿名）。biorxiv/medrxiv 是学科浏览非关键词检索：显式点名才启用，all 模式需带 category。iacr 无 JSON API，正则解析 HTML（不引入 bs4）。**测试陷阱**：直连源增多后，老测试里 sources 含直连源会打真实网络——测试一律 stub requests.get 或改用仍走后端的 google_scholar 作代表源。

**v2.9.1（2026-09-09，a487e25）**：用户 PEGDGE 11 词查询实测暴露 AND 语义源（hal/pubmed/pmc/europepmc/openaire/ieee，空格=AND）长查询全 0 命中 → `_relax_and` 逐级放宽（>6 词先蒸馏，再 AND 前 5→1 词砍尾重试，首个非空即返回），实测 hal 0→1/pubmed 0→3/pmc 0→5/europepmc 0→5。dblp 2026-09 起上 Anubis 反爬（200+HTML 质询页）→ 检测 200 非 JSON 立即报「疑似反爬拦截」不重试。**逐源实况冒烟 `scripts/live_sources.py`**：串行每源一稳定查询，PASS/FAIL/EMPTY+命中+耗时，key 从环境变量注入（config.json 里 key 名带 PAPER_SEARCH_MCP_ 前缀）。实测基线：429=共享 IP 限流（配 key 即过）、zenodo 504/openaire 超时=对方服务波动、dblp=反爬，均非代码 bug。

**v2.9.2（2026-09-09，cb85a7f）反爬代理兜底 → 已在 v2.9.3 回滚**：住宅代理是 Apify 付费 plan，且 proxy.apify.com:8000 用 API token 当密码 → 407（需控制台 Proxy 页独立 proxy password）；api-key-rotator 的 apify 转发只是 API 转发（/v2/acts query-param token），无 CONNECT 代理能力。**semantic 429 根因**：真 key 连发 3 个（间隔 2s）第 3 个仍 429 且无 Retry-After——S2 长窗口配额（~100req/5min），OWUI tool 与 paper-search-mcp 共用同一把 key 互挤 → 解法是给 tool 申请独立 S2 key。

**v2.9.3（2026-09-09，e9667fe）反爬真实解法**：Anubis 是 JS PoW，headless 浏览器天然可解、与 IP 无关 → **dblp 兜底走自托管 firecrawl**（`_dblp_via_firecrawl`：firecrawl_scrape rawHtml+waitFor 8s；hosted 侧返回 `<pre>` 包装、mcpo 侧 application/json 原样透传，两种形态兼容，实测 ~5s 穿透）。**google_scholar 可选走 Apify actor**（valve `apify_rotator_base_url` → POST rotator `/v2/acts/johnvc~google-scholar-api/run-sync-get-dataset-items` `{q,maxResults,mode:"search"}`，201 同步返回，实测 5.9s 完整结构化结果含 citations；PAY_PER_EVENT 免费层可用但限量；配了就把 scholar 从后端源列表含 all_mode 动态剔除，未配保持后端）。**Apify store 实测**：dblp actor 全废（parseforge 版自己撞 Anubis、logiover 版跑挂）——Anubis 站点只有真浏览器好使；scholar actor 多家可选。结论：无需自研 actor（firecrawl=Anubis 类零成本自托管"actor"，scholar 有现成）；后端 `PAPER_SEARCH_MCP_GOOGLE_SCHOLAR_PROXY_URL`（当前 192.168.254.253:1090）是 scholar 的另一条后路。

**v2.9.4（2026-09-09，7cdaa79）scholar 三级链**：firecrawl 首选（`_google_scholar_firecrawl_search` 抓 scholar 搜索页 markdown 解析）→ Apify actor 兜底（被拦/失败/空结果且配了 actor 时自动落）→ 两 valve 都没配才走后端。**用户路由实况**：mcpo 的 firecrawl 工具指向 api-key-rotator → 官方 firecrawl 云（非自托管实例），stealth 出口实测 2.3s 稳定穿透 scholar 无 CAPTCHA。**scholar markdown 解析坑**：作者行分隔符带 NBSP（`\xa0- `，须先归一化否则 split(" - ") 切错）；作者链接/纯文本两形态；行动线 `[Save](..)`/`SaveCite` 两形态；snippet 可多行；标题内嵌 `**` 高亮；行首可带 `\[PDF\]/\[HTML\]` 字面标签。

**v2.9.5（2026-09-09，98aa35f）scholar 链插入 tavily 第二级**：链 = firecrawl → tavily `/extract`(**必须 `extract_depth=advanced`**，默认 basic 只出标题+链接) → Apify actor（PAY_PER_EVENT 付费放最后）→ 都没配走后端；`_gscholar` 重构为 attempts 列表逐级下落。tavily advanced 怪癖（解析器兼容）：吃掉 `**` 两侧空格（`_clean_md_text` 把 `*` 换成空格再折叠）、作者行分隔符无空格（`Hong…- Nature`，正则 `\s*[-–]\s+|\s+[-–]\s*` 切）、PDF 链接不转义（`[[PDF] x]`）。exa `/contents` 被 scholar 400 拒（CRAWL_HTTP_400）、jina 被 CAPTCHA——两者不可用。实测：firecrawl 1.3s / tavily 4.6s 均 5 命中字段完整。

**Phase 3 ✅（2026-09-09，portainer-stack f2bc97dd→74418921 钉版）paper-search-mcp 退役**：新服务 `papers-service/`（FastAPI，端口 3200，镜像 ghcr.io/xyonium/firecrawl-papers-service）实现 shim 的 /papers/* 上游契约（`search_{source}`/`get_crossref_paper_by_doi`/`read_{source}_paper`，单路由 `/papers/{tool}` 正则分发，注意源名带下划线）。检索复用 tool.py 全部直连适配器（Dockerfile `ADD raw.githubusercontent .../tool.py`，workflow 把 PAPER_SEARCH_REF 解析成 main sha 传入使缓存失效；tool.py 升级靠手动 workflow_dispatch），新增 doaj 直连（`doaj.org/api/search/articles/{q}` 免 key）。read 是 9 源轻量直连（arxiv/iacr/hal/semantic=OA-pdf；pubmed=efetch；pmc/europepmc=fullTextXML 粗去标签；crossref/openalex=元数据 markdown），读不了 404 → shim 落 reach。**shim 拆分**：`PAPERS_BASE_URL`/`REACH_BASE_URL` env，缺省回落 MCPO_BASE_URL 向后兼容；reach-mcp 仍留 mcpo。**部署实测坑**：①ADD 远程文件权限坑（0600/目录无 x 位，--chmod 会连目录一起打坏）→ 加 `RUN chmod -R a+rX /srv/vendor`；②tool.py 顶层 `from mcp import ClientSession` → requirements 需 mcp 且**pin ==1.27.2**（对齐 OWUI 容器，1.30+ 删了 streamablehttp_client 别名）；③api-key-rotator 只在 open-webui-nogpu_default 网络 → papers-service 需接 owui external 网络（scholar tier2/3）。容器实测：scholar 链过 mcpo→rotator→官方云 ✓、semantic 带 key ✓、crossref doi ✓；arxiv.org 当时对本机 IP 连接重置（宿主+容器同 IP 同现象，时变封锁，非代码问题）。16 契约测试（TestClient+mock）全过。**收尾待办**：用户在 Portainer redeploy stack（compose diff 自动拉两个新镜像）→ 验证 /v2/research/papers → 确认后从 mcpo config.json 删 `papers` 服务（paper-search-mcp 真正下线；注意 OWUI tool.py 的 doaj/ssrn 等安全网也会随之消失，doaj 如需保留要给 tool.py 加直连适配器）。

**Phase 3 补强（2026-09-09 晚）**：①papers-service read 加到 12 源（ab85ee63→钉版 223c41a1）：biorxiv **PDF 全文级**（details API 取 DOI → `{doi}.full.pdf` 直链实测 200/真 PDF；拿不到退元数据）、medrxiv **仅元数据**（CDN 挂 Cloudflare，无浏览器 UA GET 直链 403 "Attention Required!"）、doaj 元数据（DOI 走 search/articles、uuid 走 articles 端点）；medrxiv/openaire 评估过不值得加全文（openaire API 是 oaf:result 深层 XML，解析成本＞收益；acm 无公开 API 永跳）。真网络 fixture 验证 12/12（arxiv 因本机时变 IP 封锁除外）。②tool.py v2.9.6（64a88e5）**下载身份闸**：download_paper_to_knowledge 两条路径（pdf_url 直下/后端落盘读回）都过 `_verify_downloaded_pdf`——PDF 全文前 6000 字符与标题 token 覆盖率 ≥60% 放行（**论文集含目标文即放行，用户明确不要大小限制**——OA 链拿不到 Content-Length）；提取失败不拦（扫描版宁放过）。背景事故：OA fallback 下过几百 MB 临床数据论文集卡死 OWUI RAG。坑：frozenset("a an the") 是按字符迭代要 .split()；中文单字 token 要单独保留（`len(w)>1` 会滤掉）。测试 14 个新增、全套 120 无回归。

**download_with_fallback 迁移 ✅（2026-09-09 深夜，d7f367fc→钉版 bba8443f；tool.py 4b0aaca v2.9.7）**：用户拍板"download 是核心功能不能漏"→ 全量盘点 tool.py 对 mcpo papers 的调用（search_papers×3 / read_*_paper×1 / download_with_fallback×1）确认 3 个缺口：read_doaj/openaire 的后端是**真全文**（下载 PDF 提取）而 papers-service 只有元数据；download_with_fallback 整条 OA 链无替代。**照搬 paper-search-mcp 0.1.4**（源码在 /mnt/docker/mcpserver/uv-cache/archive-v0/UiB763zsTDmVzlNtqw4MK/）：papers-service 新增 app/downloader.py + `POST /papers/download_with_fallback`（PDF 字节响应+X-Download-Via 头），链序=native(arxiv/iacr/biorxiv)→仓储 openaire→core→europepmc→pmc（复用 toolwrap 直连检索）→Unpaywall（UNPAYWALL_EMAIL env 注入 valve.__dict__，它本在 UserValves 不在 Valves）→可选 Sci-Hub（embed/iframe 正则解析）。**身份闸下沉到每个下载点**：实测仓储按 DOI 搜出第一篇可能是别的文章（mxene ≠ glucose sensor），闸拒后自动落下一级（原版无闸下错文档）。**实测修正**：researchProducts 端点 200 活着（tool.py 注释里的"404 已废弃"过时了）；openaire instance webresource 直链 PDF 率 0（都是 landing page，仓储层靠后续下载校验）；mdpi 整站对无浏览器指纹 GET 403（Chrome UA 一样，出版商反爬，链无能为力）；CSHL biorxiv 连发请求 429 限流。**下载点统一浏览器 UA**（自标 UA 在 CDN/出版商侧吃亏）。tool.py v2.9.7：新 valve `download_fallback_url`（默认 http://papers-service:3200/papers/download_with_fallback），留空回退 mcpo 落盘模式（自然失效）。CORE 无 key 429 实测（portainer stack env 未见配，匿名仓储层跳过它）。测试：papers-service 26、tool.py 123 全过。

**v2.9.8 部署后全面去 mcpo 化 ✅（2026-09-09 深夜，0745d00）**：用户部署后拍板"变量名也改彻底"。tool.py：`mcpo_url`→`papers_service_url`（默认 http://papers-service:3200/papers），search 安全网+read 快车道全部改走它（`_mcp_call`→`_papers_call`，新增 `_papers_base()`）；`_mcp_call_service`（firecrawl 网关）base 改从 firecrawl_base_url 反推（不再从 papers URL 剥 /papers）；`mcpo_api_key` 保留（firecrawl 网关鉴权共用）。README 重写（架构图 v2.9.8、安装段去 mcpo/config.json、致谢更新）。firecrawl 网关（scholar tier1/dblp Anubis/web 兜底）**仍走 mcpo 不退役**。部署验证：papers-service healthz 12 read/19 search、download E2E native:biorxiv 200/1MB、scholar 链经 research-proxy→mcpo→rotator→官方云 2 命中。

**v2.9.9 落盘回退删除 ✅（2026-09-09 深夜，708977b）**：用户确认"不需要的清理掉"。**共享盘的历史**：mcpo 网关传不了二进制→paper-search-mcp 把 PDF 落盘 /downloads 返回路径字符串→open-webui 必须挂同一共享卷（mcp-downloads）才能读回——纯二进制传输补丁。papers-service 是自家 FastAPI 直接 Response(content=bytes)，内存流转无需落盘。删除：`_download_via_backend` 整个函数（os 落盘/共享卷查找，-60 行）、`download_fallback_url`/`shared_download_dir` 两个 valve、`import os`；download 固定 POST papers-service（端点 URL 硬编码，测试锁定）。测试 122 全过。**清理后状态**：mcpo 只剩 firecrawl 网关一个消费点；docker 卷 mcp-downloads 可删；paper-search-mcp 彻底无残留依赖。

**聚合端点补漏 ✅（2026-09-10，4edb7f1d→钉版 2dafc29c）**：用户实测撞上——tool.py 安全网分支（`sources=doaj` 点名或 all 模式）调 mcpo 时代的**聚合端点** `POST /papers/search_papers`（多源并发+按源隔离），papers-service 只有单源 `search_{source}` → 404（"papers 服务请求失败: 404 .../search_papers"）。默认源列表不含安全网源所以平时正常，仅点名时触发（diagnostics 里 backend 分支耗时 0=被跳过的假象）。修法：papers-service 实现聚合端点（对齐 mcpo 形状 `{papers, source_results:{源:命中数}, errors:{源:错误}}`，sources= 逗号列表或 'all'，未知/未实现源跳过，每源 16s 预算 gather 并发，失败源计 0 进 errors），tool.py 零改动。research-proxy 不用聚合端点（只调单源）不受影响。契约测试 +4=30。**教训**：替代后端时要对照旧后端的全部端点形状（不止 shim 消费的）——paper-search-mcp 有 3 个消费方各用不同端点子集。

**arxiv 直连实测结论**（写适配器时验证）：export.arxiv.org 必须 https（http 301）；全词 AND 对 3+ 专精词 0 命中、全词 OR 被高频词灌噪声（**后端 paper-search-mcp 就是 OR**，同查询返回无关论文——后端质量基准很低）；解法是逐级放宽（≤5 词 AND → 砍尾词 → 单词）。注意稀有词歧义（iCVD 也匹配 Infant Care Video Dataset）。

**Why:** 后续 Phase 1 剩余源的实现要复用同一模式（anyio.to_thread + RuntimeError 进 errors 字段 + monkeypatch requests.get 的测试），且 shim 的 MCPO_BASE_URL 契约是 Phase 3 的对接点。
**How to apply:** 继续该计划时先看 tool.py 的 `_arxiv_search`/`_pubmed_search` 模式和 tests/test_arxiv.py；firecrawl 侧对接看 [[firecrawl-portainer-selfhost-setup]] 的 research-proxy 段落。
